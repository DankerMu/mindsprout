## Code Canonicality

Same logic must have exactly one implementation in the repo. Version evolution belongs in git history, not in filenames or identifiers.

- Before adding any function, class, module, or file: grep the codebase for existing similar implementations. If found, extend or refactor the existing one. Only create new if truly absent.
- Forbidden suffixes for filenames, class names, function names, and module names: `_v1`, `_v2`, `_v3`, `_new`, `_old`, `_backup`, `_temp`, `_copy`, `_final`, `_real`, `_improved`, `_refactored`, `_fixed`, `_legacy`, `_deprecated`. If one exists already, treat it as debt to unify, not a pattern to extend.
- Refactor in place: commit the working state first, modify the original file, run tests. If it breaks, `git revert`. Never keep an old version alongside the new "just in case" — git is the safety net.
- No parallel implementations as a transition. Without a written cutover exception, do not ship v2 while v1 still exists; replace atomically.
- Commented-out code is a lint error, not a safety net. Delete it; git remembers.
- Unreferenced exports and dead code paths are debt. Wire them up in the same change or delete them.
- Do not use the repo as a scratchpad. Directories like `tmp/`, `scratch/`, `backup/`, `_old/`, `deprecated/`, `archive/`, `wip/` must not appear in commits.
  - The one exemption is OpenSpec's fixed archive path `openspec/changes/archive/` (scratch directories below it are still rejected; [decision 0007](decisions/implemented/process/0007-openspec-archive-exempt-from-scratchpad-guard.md)).

## Conventions

### Naming

- Files: kebab-case for modules, `PascalCase.tsx` for components. Identifiers: camelCase / PascalCase / UPPER_CASE (`@typescript-eslint/naming-convention`). Forbidden suffixes: see Code Canonicality.
- Tests: `*.test.ts(x)` beside the source file; integration under `tests/integration/`, contract under `tests/contract/`, e2e under `e2e/`.

### Debt markers and deviations

- `FIXME` blocks the next release; `TODO` fix when resources allow; `XXX` maybe someday. Every non-default configuration value carries an inline comment naming its motivating failure mode; an empty catch names what it swallows.

### Commit format

- Conventional commits required: `<type>(<scope>): <Subject>` (sentence case, ≤72 chars). Types: `feat`, `fix`, `refactor`, `chore`, `docs`, `test`, `ci`, `build`, `perf`. Scopes: `map`, `ai`, `account`, `export`, `app`, `shared`, `ci`, `docs`.
- Breaking changes: body line starting `BREAKING CHANGE:`. Enforced by `commitlint` (`commitlint.config.cjs`, commit-msg hook). Template: `.gitmessage`.

### Pull requests

- Use `.github/PULL_REQUEST_TEMPLATE.md`. Required sections: Summary, Test plan, Runtime evidence, Risk, Decision record.
- Reviewers: the `risk-adaptive-cross-review` pass (reviewer + verifier subagents); the owner performs functional acceptance only.
- Diff limit 400 lines, CI-enforced (`layer6-diff-size-guard`); split or add `diff-limit-exempt` with a justification. A `changeset` accompanies every user-visible change.

### Branch model

- Trunk-based on `main`; feature branches `agent/<issue>-<slug>` (humans: `<author>/<short-slug>`), one task = one branch, rebase before PR.
- Branch protection on `main`: required status checks `All checks passed`, `Lockfile–manifest consistency`, `PR diff size guard`; `strict`: the branch must be up to date with `main` before merge; linear history; no force-push. Human approving review not required (decision 0001).
- Stacked PRs: use `gh stack` or land sequentially; never delete a branch an open PR bases on. Rewriting pushed history only with `--force-with-lease`, never raw `--force`.

### Coverage threshold

- Minimum 90% line/branch/function coverage **per file** (`vitest.config.ts`); CI fails below. An uncovered line is a dead-code candidate first, a missing test second.
- Route components are the only exclusion (`constraints.yaml` `exemptions`); every future exclusion carries a reason and an exit condition there.

### Documentation discipline

- Docs change with code in the same PR (config keys, defaults, error codes, routes). `pnpm docs:check` fails on dead links and missing required sections (`docs/.docgate.json`); allowlist entries carry a reason and exit condition.
- Public surfaces carry a `## Known Limitations` section. Generated catalogs are regenerated, never hand-patched. One home per fact; link, do not copy. Prose rules: `.claude/skills/prose-contract/SKILL.md`.

## Code Review Self-Check

- Can explain "why this approach" vs the nearest obvious alternative; matched existing patterns unless there is a stated reason to diverge; addressed the bug/feature at the correct layer, not by silencing a symptom.
- Ran the checks selected per `### Scoped verification` and they pass on this branch (full `pnpm check` only when the change is repo-wide or CI needs diagnosing).
- Added/updated tests first and verified they fail before the fix and pass after; shipped the decision record if the change is non-trivial; updated docs only where they materially help.
- No canonicality violations (`_v2` files, duplicated logic, dead exports, scratch dirs); no hidden dependencies (implicit global state, undocumented environment-only behavior).
- Diff focused (≤400 lines, no drive-by refactors); PR description states intent, approach, test plan, risk, and what was not tested.

## Architecture Discipline

### Domain-Driven Design (strict)

- Vocabulary: `openspec/glossary.md`; contexts and invariants: `CONTEXT.md`. A term that conflicts with the glossary is surfaced, never silently synonymised.
- One transaction touches one aggregate. Contexts never import each other's domain types; translation lives in `src/contexts/<ctx>/acl/`.

### Test-Driven Development (required)

- Red → green → refactor → commit. No production code without a failing test first; a new `src/**` file without its paired test fails pre-commit (`scripts/check-test-pairing.sh`).
- Forbidden: disabling tests to pass CI; `it.skip` without a linked issue and deadline; "no exception thrown" tests; mocking the system under test. A flaky test is a bug: quarantine with an issue, fix or delete within 14 days.

Full clauses (layering table, aggregates, repositories, domain events, cadence, mutation testing, boundary integration tests, isolation): `docs/engineering/architecture-discipline.md`.

## Agent Operating Rules

### What agents may do

- Commit to feature branches (`agent/<issue>-<slug>`); open PRs targeting `main`; run every script in `package.json`; propose updates to `AGENTS.md` (owner acceptance before merge).

### What agents may not do

- Push to `main`; force-push any shared branch; use `--no-verify`; run destructive database operations against any non-local environment; deploy to production.
- Upgrade dependencies inside a feature PR (Renovate only); modify CI/hooks/`constraints.yaml` without flagging it in the PR and running `pnpm test:guardrails`.
- 不得改弱门禁来让自己通过 — lowering a threshold, adding `eslint-disable`, skipping a test, or editing a gate to fit a change needs its own decision record first.
- Call a real paid AI key from tests, CI, or local verification.

### Commit attribution, skills, memory

- Agent-authored commits end with `Co-authored-by: <agent name> <noreply address>`.
- Skills live in `.claude/skills/` (my-agents packs + repo-local `pre-push-checks`, `prose-contract`, `decision-record-lifecycle`); Codex reads this file directly.
- No special memory boundary beyond secrets: never persist key values or user map content across sessions. Scratch files go to `/tmp/`, never the working tree.

### Decision records

- A non-trivial change ships its record in the same PR (`decisions/`, four-zone lifecycle, `pnpm decisions:check`). Procedure: `.claude/skills/decision-record-lifecycle/SKILL.md`. Mechanical/local edits are exempt and say so in the PR.

### Evidence requirements

- Success claims require fresh command output from the current session: command + exit code + relevant output. **Verify the world, not the self-report**: re-run the command, re-read the file, hit the endpoint. When a claim implies "nothing else changed", assert it.
- UI claims require a screenshot + zero new console errors. A success claim without fresh output is unverified.
- PRs include `## Runtime evidence`; "None — review-only change (reason: …)" is the only escape hatch.

### Scoped verification — evidence matches the surface

- Select the narrowest check covering the changed behavior; report only commands actually run. Table and procedure: `.claude/skills/pre-push-checks/SKILL.md`.
- Never default to the full suite; CI owns exhaustive coverage. Derive the change list via `pnpm change-scope <base-ref>` — never from a guessed upstream. Coverage scope names the affected files explicitly; never hide an uncovered file behind a narrowed include.

### Iteration loop gates

- Max 3 fix-and-recheck cycles per failing check, then stop and report (the `subagent-workflow` fix gate enforces this for implementer/reviewer spawns). Never weaken, skip, or delete a test to get green. Checkpoint commit at every green state. One task = one branch.

### Protocols kept in full elsewhere

- Binding protocols in `docs/engineering/agent-operating-rules.md`: debugging CI failures (layer classification, reproduce-locally rule), environment tiers (local full / staging via CI / prod none), concurrency (separate worktrees, rebase, lockfile merges).
- Same file: generated artifacts (lockfile pairs with manifest; snapshots reviewed hunk by hunk, CI never writes them), incident-to-constraint ratchet (>30 min lesson → dated note; third same-class incident → a check).
- Secrets: never read, cat, or print `.env*` files; `.env.example` is the only secrets-adjacent file agents open; reference secrets by variable name only. Deny list in `.claude/settings.json`.

### Known blind spots (handed to review)

- Coverage gate: proves lines ran, not that assertions are meaningful — the reviewer agent checks test strength; Stryker reports survivors weekly.
- Docs gate: verifies file existence and section presence, not content accuracy. Contract snapshot: catches drift in `schemas/openapi.yaml` only — a route never registered there is invisible; `## Where new behavior goes` makes registration part of adding a route.
- Secret regex guard: catches known credential shapes only; gitleaks in CI is the broader net, and neither sees a secret pasted into a decision record's prose. A declared blind spot is a review obligation; an undeclared one is a hole nobody owns.
