# Design

## Context

Owner decisions: full installed tree per platform (runtime/dev, direct/transitive and installed optional dependencies), not every uninstalled lockfile platform; exact current-version copyleft exceptions, not global MPL/LGPL permission. Approval: issue68 comment6718121355 and .workplans/68/owner-policy.md. Native inventory on macOS contained640 name/license groups and692 version entries; these counts are evidence, not hard-coded expectations.

## Goals / Non-Goals

Governing invariant: every reported installed package version must have an exactly approved declared license or an exact package-name/version/license exception; no absent, malformed or failed inventory can produce a compliant result.
Change surface: constraints.yaml policy, one read-only Node CLI, focused CLI tests, package scripts, existing CI anti-drift step and existing documentation mirrors.
Must preserve: original six allowed IDs, every existing gate/threshold/check identity, runtime dependencies and versions, repository cwd-based script convention, and unchanged application behavior.
Sibling surfaces: pnpm inventory producer and its per-package versions arrays, YAML policy parser, exact exception matching, CLI exit status/diagnostics, local check path, Linux CI gate and policy/verification docs.
Non-goals: legal compliance certification; scanning bundled/vendored source; registry auditing of all absent platforms; SPDX expression evaluation; license replacement/migration; package upgrades; weakening another gate; solving #88 mutation runtime.

## Policy and Interfaces

Keep dependencies.allowed_licenses.value as the allowlist; add scope: installed-all, severity:block and enforcement metadata. Add exceptions as two groups, each with packages (explicit complete names, no wildcard semantics), version, license, reason and exit_condition. Grouping shares rationale only; matching remains exact per name/version/license.
General IDs add Unlicense, MIT-0, CC0-1.0, BlueOak-1.0.0, Python-2.0 and CC-BY-4.0. Exact groups: lightningcss plus11 locked platform packages at1.33.0/MPL-2.0, and10 locked @img/sharp-libvips platform packages at1.3.4/LGPL-3.0-or-later. Use the full metadata-verified names in .workplans/68/inventory/platform-package-metadata.json. Remove exceptions when unused dependencies disappear; upgrades or license changes require new owner approval.
licenses:check runs node scripts/check-licenses.mjs from process.cwd(), reads constraints.yaml and invokes pnpm licenses list --json without a shell or dependency-type filters. Exit0 means compliant nonempty inventory; exit1 means policy violations with package/version/license diagnostics; exit2 means usage/config/inventory acquisition or shape failure. Exact license strings only: UNLICENSED, unknown values and composite expressions are not inferred from substrings or automatically repaired.
Inspect every entry in each versions array. No name-prefix match, case folding, version range or first-version shortcut. An empty inventory, missing required policy fields, empty allowlist, malformed exception, invalid package/versions/license shape or failed producer is an error, never an empty pass.
Use direct dev yaml2.9.1 for YAML parsing rather than regex or an undeclared transitive import. Generate lockfile through pnpm. Keep the script read-only; diagnostics do not dump unrelated package metadata or environment values.
Node's test runner exercises the public CLI using isolated temporary projects, real tarball packages served by a loopback npm registry, and native pnpm inventory; no mocked system under test, inventory echo shim, permanent source-text tests or production test-only flags. Await registry readiness before asynchronous child installs, await installs before shutdown, and close the owned server/remove owned temporary directories and store data on both success and failure. Native file/link dependencies whose inventory versions are unresolved remain fail-closed inputs, not a source of inferred versions.

Fixture child processes use an explicit environment allowlist: caller PATH for the installed toolchain, owned HOME/XDG/temp paths, CI/noninteractive settings and owned empty npm user/global config files. Do not inherit registry/authentication, npm lifecycle or NODE_OPTIONS settings and never inspect user credential values. Apply the same environment to install, inventory, checker and tar children; the fixture project's .npmrc is their single registry/store source. The production audit continues to use its real installation context, not fixture overrides.

## Verification Sequence

1. Tests first. An absent command is setup evidence only. Bootstrap the callable CLI by collecting real native inventory, without claiming enforcement; then run a real forbidden-license fixture and observe semantic RED (inventory includes that package but CLI incorrectly succeeds). Do not count missing-module collection errors as the required RED. The inventory-only bootstrap is uncommitted intermediate work, replaced before delivery, not a fallback or parallel implementation.
2. Implement the smallest general-ID enforcement tracer and observe GREEN for allowed/forbidden native fixtures. Add exact-exception/multiple-version and fail-closed malformed/empty cases incrementally, observing the relevant RED before each change. Parent runs verification after each implementer yield; implementer skips test/build/lint/format commands mid-flight.
3. Run pnpm licenses:check against the real macOS tree and focused contract tests. Check exceptions bind exact names, versions and licenses, including an unauthorized second version, a lookalike package and changed license. Keep deterministic tests independent of the repository's incidental current package counts.
4. Wire test:licenses and licenses:check into anti-drift and the existing CI anti-drift job before dead-code inspection. Run scoped lint/typecheck/docs/decisions/guardrails and frozen install; Linux CI must pass the real audit at the final head. No standalone green self-report substitutes for actual CLI output.
5. Build an owned unmerged child PR with a pinned registry dependency outside the approved policy: tinymce8.0.1 declares GPL-2.0-or-later, has no dependencies or install scripts, and its metadata was verified. Add it only to the probe's runtime dependencies to complement the local transitive-dev case; generate package/lock changes via pnpm in an isolated temporary directory, never hand-edit lockfiles. Native CI must reach the license-audit step and reject that exact package/version/license for the intended reason, not fail during install or earlier setup. Preserve compare/log/head evidence; close the probe, delete its owned ref and remove temporary directories. The canonical branch retains no probe dependency.
6. Obtain full-depth review and owner acceptance of the new gate evidence. Merge only after exact-head required CI and harness checks pass; unrelated advisory #88 is disclosed, not suppressed.

## Risks / Trade-offs

Installed-tree scope omits platform-specific packages absent on the current host; local macOS and Linux CI provide distinct evidence, not a claim about every platform. Existing22 restricted-license platform variants were separately metadata-verified. The gate checks declared metadata only, not legal obligations or the contents of bundled binaries.
Unknown/composite licenses fail closed rather than adding an SPDX evaluator. Exact-version exceptions deliberately stop an unreviewed upgrade. Permission to depend on a package does not waive notice, source or distribution obligations.
Record the accepted policy in `decisions/implemented/process/0015-installed-dependency-license-audit.md` under the decisions/README.md conventions before task1.3 widens the constraints.yaml allowlist or adds exceptions. Rollback is a reviewed revert, never deleting a test or exempting the new check to make an otherwise invalid tree pass. Keep AGENTS within its existing byte budget without dropping rules or changing the user-owned instruction guard.

Oracle correction before enforcement: native pnpm reports `versions: [null]` for the original local `file:` fixtures despite their manifests' versions. Logs01/02 are preserved as setup/discovery, not the qualified semantic RED. Switching fixture transport to a real registry preserves the original allowed-MIT/forbidden-GPL expectations while giving the producer resolvable versions. The CI probe uses a verified forbidden registry package instead of an unversioned local fixture; rejection for an unapproved declared license is unchanged. Evidence: `.workplans/68/review/oracle-correction.md`.

Further oracle setup evidence: log03 failed because installation used the owned store while inventory resolved the default store. Log04 then reached an unintended public-registry lookup through inherited caller configuration; its authorization was automatically redacted. These are setup failures, not qualified RED. The fixture must bind every native child to the same owned configuration/environment before policy behavior is judged.
