# Design

Change surface: `package.json` `pnpm.patchedDependencies` (second entry); `patches/@stryker-mutator__util@10.1.1.patch` (generated by `pnpm patch` / `pnpm patch-commit`, edits shipped `dist/src/errors.js` only); `pnpm-lock.yaml` patch metadata; `scripts/stryker-vitest-runner-patch.test.mjs` (extend; same `pnpm test:stryker-patch` script and CI step); decision 0022 patch inventory; `docs/engineering/dependency-patches.md` current patches + Known Limitations.

Must preserve:

- Installed versions stay exactly `@stryker-mutator/util@10.1.1`, `core@10.1.1`, `vitest-runner@10.1.1`, Vitest 5.1.0; the #118 vitest-runner patch stays applied and its 4 regression scenarios still pass.
- `errorToString` output for every input that does not throw today is byte-identical: falsy → `''`; errno `Error` → `name: code (syscall) stack`; `Error` with stack → `name: message\nstack`; `Error` without stack → `name: message`; string → itself; ordinary object → `[object Object]`.
- Runner `RuntimeError` classification, mutation scope, thresholds, timeouts, CI budgets (#88) unchanged; no try/catch added in the runner.

Must add/change: `errorToString` is total for values where `String(value)` throws, exactly as stryker-js#6226 (input → patched output; unpatched error):

- null-prototype `{name:'TypeError', message:'expected error', stack:'TypeError: expected error\n    at foo.js:1:1'}` → `'TypeError: expected error\nTypeError: expected error\n    at foo.js:1:1'`; unpatched `TypeError: Cannot convert object to primitive value`.
- null-prototype `{}` → `'[object Object]'`; unpatched `TypeError: Cannot convert object to primitive value`.
- `{ [Symbol.toPrimitive]() { throw new Error('not convertible') } }` → `'[object Object]'`; unpatched re-throws `Error: not convertible`.
- null-prototype `{message:'m'}` (non-string name) → `'m'`; unpatched `TypeError: Cannot convert object to primitive value`.
- null-prototype `{name:'E', message:'m'}` (non-string stack) → `'E: m'`; unpatched `TypeError: Cannot convert object to primitive value`.

Governing invariant: formatting an error for a report never throws; it returns the best available text and leaves the original error result intact.

Sibling surfaces:

- All `errorToString` consumers resolve the single installed `@stryker-mutator/util@10.1.1` (core `child-process-proxy-worker.js`, `child-process-test-runner-worker.js`, `retry-rejected-decorator.js`, `command-test-runner.js`, initializer `npm-client.js`/`npm-registry.js`, util `stryker-error.js`, vitest-runner `vitest-test-runner.js`): the patch fixes them all; verify by realpath that the runner's `@stryker-mutator/util` import resolves to the patched store entry.
- #118 patch and decision 0022 mechanism: second patch entry must coexist; `pnpm native:installed` and `pnpm native:install:test` (0021 contract) still pass.
- Destructuring `name/message/stack` inside the catch can itself throw for exotic inputs (throwing getters, revoked Proxy); upstream does not guard this. Non-goal: mirror upstream exactly; record as Known Limitation.

Seams under test:

- Formatter: import `errorToString` from the installed `@stryker-mutator/util` resolved from the vitest-runner's store entry (realpath must contain `@stryker-mutator+util@10.1.1_patch_hash=`), never a copy.
- Runner: installed `VitestTestRunner` with `vitestWrapper.createVitest` stubbed (as in the #118 test). The #118 `circularContext` only covers `init()`; the stub ctx must also provide `ctx.provide`, `ctx.state.filesMap` (with `clear()`), writable `ctx.config.related`, `ctx.projects` (`forEach`), async `ctx.start()`, `ctx.state.getFiles()` → `[]` (called by `run()` twice, then by `readMutantCoverage` on dryRun or `readHitCount` on mutantRun, also on the error path), and `ctx.state.errorsSet` = `Set{ null-prototype {name:'TypeError', message:'worker lost', stack:'TypeError: worker lost\n    at w.js:1:1'}, new Error('readable') }`. Calls: `dryRun({ files: [] })` and `mutantRun({ activeMutant: { id: '1' }, testFilter: undefined, sandboxFileName: <temp file>, hitLimit: undefined, mutantActivation: 'runtime' })` (adjust to the installed option shape; both go through `run()`, `vitest-test-runner.js:187`). Because a missing stub member also throws a `TypeError`, unpatched checks match the exact message. Temp cwd and env restore as in the #118 test.

Required evidence:

- Formatter, unpatched util 10.1.1 → each of the five new inputs throws the unpatched error listed in Must add/change (matched on message text); patched → returns exactly the listed string. Existing-output table above asserted on both.
- Runner `dryRun`, unpatched → rejects with message `Cannot convert object to primitive value`; patched → resolves `{ status: 'error' }` whose `errorMessage` starts `An error occurred outside of a test run: ` and contains `TypeError: worker lost\nTypeError: worker lost` and `Error: readable`.
- Runner `mutantRun` (the path of all 15 observed failures), unpatched → rejects with the same message; patched → resolves `{ status: 'error' }` via `toMutantRunResult` (`api/dist/src/test-runner/run-result-helpers.js:39-43`) with the same `errorMessage` prefix and contents — evidence that the result stays an error result (Stryker records it as RuntimeError, unchanged classification).
- Lockfile delta (measured): a second `patchedDependencies` entry; util snapshot key becomes `'@stryker-mutator/util@10.1.1(patch_hash=…)'`; the util references under the core, instrumenter and vitest-runner snapshots gain `(patch_hash=…)`; those three packages' own keys, the root importer entries and the runner's store folder name (the #118 regex) stay unchanged. Any other delta is reported.
- `pnpm install --frozen-lockfile` from clean `node_modules` → exit 0; installed util `errors.js` contains the try/catch; installed runner still has the #118 `%O` line.
- Negative path re-measured for the util entry: mismatched key with frozen install → non-zero (`ERR_PNPM_LOCKFILE_CONFIG_MISMATCH`); then reverted.
- `pnpm test:stryker-patch`, `pnpm native:installed`, `pnpm native:install:test`, `pnpm test:guardrails`, docs/decisions/anti-drift gates exit 0.

Non-goals: guarding exotic property access beyond upstream; reclassifying the 15 observed RuntimeErrors; #88 budget; #135 local sandbox OOM; upgrading Stryker.

Review focus: patch byte-matches upstream intent and is minimal; existing outputs unchanged; runner scenario truly reaches `errorsSet.map(errorToString)` through the installed files; lockfile delta is metadata-only; decision/doc inventory accurate.
