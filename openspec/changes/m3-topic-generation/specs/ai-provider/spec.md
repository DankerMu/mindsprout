# Spec Delta

## Purpose

Turn a topic into a stream of validated TreeOps through one provider-neutral port, so every model transport (Claude direct, OpenAI-compatible, mock) yields the same safe op stream for the map.

## ADDED Requirements

### Requirement: One provider is configured from server environment

The server SHALL select at most one platform provider from `AI_PROVIDER` (`openai-compatible`, `anthropic` or `mock`) and its model from `AI_MODEL`. Provider keys and base URLs SHALL exist only in server environment, never in the client bundle, logs or database. No model id SHALL be built into the code.

#### Scenario: AI not configured

- **WHEN** `AI_PROVIDER` is unset
- **THEN** the application starts normally and generation reports `ai-unavailable` without calling any provider

#### Scenario: Partially configured provider fails at load

- **WHEN** `AI_PROVIDER=openai-compatible` is set but `OPENAI_API_KEY`, `OPENAI_BASE_URL` or `AI_MODEL` is missing
- **THEN** environment loading throws an error naming the missing variable

#### Scenario: Claude provider configuration

- **WHEN** `AI_PROVIDER=anthropic` is set with `ANTHROPIC_API_KEY` and `AI_MODEL`
- **THEN** environment loading succeeds, and `ANTHROPIC_BASE_URL` is used only when it is set

#### Scenario: Mock refused in production

- **WHEN** `AI_PROVIDER=mock` and `NODE_ENV=production`
- **THEN** environment loading throws

### Requirement: Generation emits only validated add_children ops with fresh ids

For a topic and the map's primary root id, a provider SHALL emit only `add_children` TreeOps. Each op SHALL target the primary root or a node emitted earlier in the same generation and SHALL append without an index. It SHALL carry children with non-empty text and ids freshly generated by the server, never ids chosen by the model. Every emitted op SHALL pass the TreeOp schema.

#### Scenario: Model temporary ids are replaced

- **WHEN** the model calls the tool with parent `root` and children with temporary ids `a` and `b`, then calls it with parent `a`
- **THEN** the first op targets the primary root id, the second op targets the server id that replaced `a`, and no emitted id equals `a` or `b`

#### Scenario: Unknown parent is invalid output

- **WHEN** the model references a parent id that was never emitted
- **THEN** the call is rejected as invalid output and no op is emitted for it

#### Scenario: Duplicate temporary id is invalid output

- **WHEN** the model reuses a temporary id already used in the same generation
- **THEN** the call is rejected as invalid output

#### Scenario: Malformed tool input is invalid output

- **WHEN** a tool input has an unknown field, an empty children list or a non-string text
- **THEN** it is rejected as invalid output and never repaired

### Requirement: Generation is bounded

A generation SHALL emit nodes at most two levels below the primary root, at most 7 children per parent counted across calls, and at most 60 nodes in total. Output beyond a bound SHALL be dropped, not rejected. Reaching the total SHALL end the generation normally and stop the provider call. Each provider request SHALL cap output at 8000 tokens and at 4 model turns.

#### Scenario: Third level dropped

- **WHEN** the model adds children under a node two levels below the root
- **THEN** that call emits no op and the generation continues

#### Scenario: Per-parent overflow truncated

- **WHEN** the model gives a parent 9 children across its calls
- **THEN** only the first 7 are emitted

#### Scenario: Total cap ends generation

- **WHEN** emitted nodes reach 60
- **THEN** no further op is emitted, the provider call is aborted and the generation completes normally

### Requirement: Failed attempts retry once only before the first op

A transport failure or invalid output SHALL trigger exactly one fresh attempt if no op has been emitted yet. A failure after the first op SHALL end the generation with an error and no retry. Client-initiated aborts SHALL never retry. Provider SDK built-in retries SHALL be disabled.

#### Scenario: Retry succeeds

- **WHEN** the first attempt fails before emitting any op and the second attempt succeeds
- **THEN** the generation emits the second attempt's ops and completes

#### Scenario: Retry exhausted

- **WHEN** both attempts produce invalid output before any op
- **THEN** the generation ends with error code `invalid-output`

#### Scenario: Failure after first op

- **WHEN** a transport failure happens after two ops were emitted
- **THEN** the generation ends with error code `provider-error`, the two ops stand, and no second attempt starts

### Requirement: Generation has a total time limit

A generation SHALL end with error code `timeout` and abort its provider call 30 seconds after it started, if it has not completed earlier.

#### Scenario: Slow provider

- **WHEN** a provider has not finished 30 seconds after the request started
- **THEN** the provider call is aborted and the generation ends with `timeout`

### Requirement: Refusals and errors never leak provider detail

A model refusal SHALL end the generation with code `refused`. Error messages exposed beyond the server SHALL be fixed texts per code (`timeout`, `provider-error`, `invalid-output`, `refused`, `ai-unavailable`). They SHALL never contain provider response bodies, keys or the user's topic. Logs and traces SHALL NOT contain the topic text or keys.

#### Scenario: Provider HTTP error body withheld

- **WHEN** the provider answers an HTTP error whose body contains the key prefix and a request id
- **THEN** the surfaced error is `provider-error` with its fixed message and the log entry contains neither the body nor the key

### Requirement: Prompt states one unified contract

Generation SHALL use one unified instruction for all adapters. It SHALL ask for two levels below the root, 3–7 children per parent, each child at most 40 characters without paragraphs, mutually exclusive siblings, output language following the topic, and changes only through the tool, one parent per call, using temporary ids with `root` for the primary root.

#### Scenario: Same contract for every adapter

- **WHEN** the Claude and OpenAI-compatible adapters build a request for the same topic
- **THEN** both carry the same instruction text and the topic only in the user turn

### Requirement: Mock provider is deterministic

The mock provider SHALL produce the same op sequence for the same topic. For an ordinary topic, the sequence SHALL be 4 first-level children followed by 3 children under each, through the same validation and id replacement as real providers. The reserved topics `mock:error-after-2` and `mock:invalid-first` SHALL respectively fail after two ops and produce invalid output on every attempt.

#### Scenario: Deterministic skeleton

- **WHEN** the mock provider generates for topic `学习 TypeScript` twice
- **THEN** both runs emit 5 ops with identical texts and structure (ids differ)

#### Scenario: Scripted mid-stream error

- **WHEN** the mock provider generates for `mock:error-after-2`
- **THEN** exactly two ops are emitted before a `provider-error`
