# Native navigation profiling

## Contract

Change surface: the existing `native:browser` entrypoint, a narrowly scoped profiling helper and its tests, installed-native composite action, and native operational guide.
Must preserve: default commands, candidate-manifest handling, 5000ms assertions, browser-noise assertions, API-first ordering, source/cache ownership, and the existing 10000ms process-group shutdown.
Must add: `pnpm native:browser MODE FRESH_OUTPUT_DIRECTORY [CANDIDATE_MANIFEST] [--profile]`, with `--profile` last and at most once. Reject unknown/misplaced/duplicate flags or surplus arguments before source/cache/profile mutation. An unprofiled run neither sends profiler commands nor touches even a pre-existing `.next-profiles`.
Governing invariant: a diagnostic replay is evidence about a failed qualification, never a replacement qualification.
Sibling surfaces: both native modes, retained/fresh browser pages, every server generation, normal/failure/signal cleanup, Linux installed-native and candidate-native callers.

## Collection

Use documented `next dev --experimental-cpu-prof`; the Node 22.23.4 pilot produced both CPU roles under normal shutdown. Before importing Next or mutating source/cache/profile state, both invocation modes reject any ambient `NEXT_CPU_PROF`, `NEXT_CPU_PROF_DIR`, `__NEXT_PRIVATE_CPU_PROFILE`, `NEXT_TURBOPACK_TRACING` or `NEXT_TURBOPACK_TRACING_PATH`, with a fixed error and no values. Do not alter Next's exit timeout or enable opaque/remote tracing.
Own the otherwise absent `.next-profiles` directory with `lstat` checks (including broken symlinks), create it exclusively, and verify directory identity before each move. Preserve unexpected content. Raw inputs must be no-follow regular-file descriptors with capped reads and before/after identity/size/mtime checks; changed files yield fixed partial codes.
Isolate raw CPU/trace files per generation after verified shutdown and before restart; never pick the newest of multiple role matches. Separate dev-main/dev-server results expose missing or ambiguous roles. Exclude any pre-start trace from the probe's owned working cache; original cache backups stay untouched. Parse bounded NDJSON arrays. Trace coverage is always observed-only because rotation/unflushed tails cannot prove full compiler history.
Use CDP `Profiler` only. Start before navigation; stop before suspension/closure; restart only after SIGCONT and record the gap. Bound operations to 1000ms; a timed-out/disconnected session is abandoned without retry, and late replies cannot revive it. No requests while suspended. Profiling shutdown stays inside the existing browser-close budget; process-group shutdown remains unchanged.
Construct fresh fixed-schema objects field by field: fixed-enum CPU categories/buckets, approved finite numeric values, allowlisted span names and fixed route classes only. Never spread raw objects or emit raw/hashed function names, URLs, paths, tags, stack strings, credentials or errors. Catch collection errors locally as fixed codes, never forwarding original messages into existing record/result/cleanup/stdout/stderr sinks. Diagnostic server logs remain private.
Ingestion/retention bounds: 16 MiB/file (capped descriptor read), 15 raw reads and 64 MiB/run; five server generations/eight browser intervals; 50000 nodes, 250000 samples, 300 one-second CPU buckets; 20000 trace records/file and 2000 accepted spans/generation; 1 MiB total safe JSON. Cap-plus-one/empty/malformed/late input yields partial codes. These do not bound Next's raw producer memory/disk or CDP inbound allocation before receipt; do not claim otherwise.
Provenance: validated workflow SHA, actual checkout SHA, PR head SHA (unknown locally), run/attempt, Node version, OS/architecture, native target/binary digest; mode/generation/trial/page/profile role; collector before/after brackets and observed launcher/process-group identity. Unobserved profile PID is explicitly null, never inferred from the launcher. No arbitrary environment value is copied.
Clocks: collector epoch/elapsed milliseconds; trace startTime epoch milliseconds and timestamp/duration hrtime microseconds; Network timestamp monotonic seconds and wallTime epoch seconds; CPU start/end/deltas microseconds on an unspecified monotonic origin. Known-value tests retain these distinctions without cross-domain subtraction. Host load/memory and collector lag are bounded context, not proof of runner contention.
CPU sample counts and interval histograms are not CPU utilization or wall-clock attribution. A native/compiler wait can remain unresolved; collection must report that limitation rather than invent a cause.

## CI and publication

Keep both qualification commands unprofiled. Exactly one separately labelled diagnostic follows an eligible non-cancelled Darwin browser-step failure, selected by that step's outcome; never both modes, installation/setup failure or cancellation. Linux and successful qualifications perform no diagnosis or diagnostic-artifact requirement.
Eligibility requires a valid failed result for the selected mode, successful source/cache cleanup with matching original/restored source hashes and no cleanup errors, and unchanged current source identity. Cleanup-blocked/missing/malformed evidence is recorded as ineligible without invoking another browser probe. The probe's existing unused-port/source/cache checks still apply. Diagnostic output is fresh and distinct from original qualification evidence.
Do not add `continue-on-error`, retries, warmup, deadline/cache changes or aggregate exceptions. Original step/action/job/aggregate failure stays authoritative for every diagnostic outcome. Publish one bounded regular non-symlink `summary.json` from a fresh owned safe-staging directory through a literal path in a separate artifact; raw outputs stay outside existing upload globs. On output overflow use a small fixed-schema partial summary; no raw fallback. Preserve original qualification artifacts.

## Evidence and review

Seams under test: opt-in CLI parsing; privacy/limit projections with hostile strings; ownership conflicts and partial cleanup; profiler state across suspension/disconnection; both native mode invocations; CI failure-to-diagnostic selection and unchanged failure propagation.
Required checks: `pnpm native:browser:test` (new behavioral red→green plus existing contracts), `pnpm test:guardrails`, strict fixture validation, scoped lint/format, docs/decision gates, and independent gate/privacy review. Execute the actual CI preflight/selection with failed-restored, failed-source, cleanup-blocked/malformed, successful, Linux and installation-failure inputs; only the two eligible failures launch their one matching mode.
Runtime matrix on Node 22.23.4 and an owned scratch database: both `restored-lifecycle ... --profile` and `source-change ... --profile` must emit safe complete-or-explicit-partial evidence and retain their real functional exit; an unprofiled control must emit no profile artifacts/commands. Every run must restore source/cache/profile-directory state. Exercise interrupt/failure teardown and inspect all published-safe filenames for rejected sentinels. One attributable CI capture must retain the natural original failed qualification and artifacts, with the required job red regardless of diagnostic outcome.
Non-goals: fixing #199/#203, changing application code/auth behavior, native patches/recipes/packages, dependencies, cache policy, qualification thresholds, or claiming local non-reproduction is a repair.
Review focus: false-green CI paths; raw-data publication; clock/CPU interpretation; bounded asynchronous collection; ownership and cleanup on every exit.
