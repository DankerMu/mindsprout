# Design

## Context

See [proposal](proposal.md). `observeNavigation` already observes RSC/scripts and Performance snapshots, but excludes API response lifecycles and clears its request map at outcome. `visitEditor` owns the exact five-second clock; `waitForReadiness` owns the unchanged visibility assertion. `probeTimeline` samples another experiment after readiness and is not a pre-create visibility oracle. Existing runtime-profile, fixed projections, compact summary and owned safe publication remain canonical.

## Goals / Non-Goals

Governing invariant: observation describes the original readiness outcome; it never changes or substitutes for that outcome.
Goals: distinguish observed API/RSC network delivery, SPA URL/history changes and sampled marker visibility in one diagnostic invocation, without claiming repository promise resolution or a React commit.
Must preserve: installed/candidate grammar; both modes; default no extra diagnostic commands/listeners/sampling; original click/readiness ordering, source stimulus, browser noise, cache, signals, process ownership and close budgets.
Non-goals: product changes, performance repair, reruns, prefetch/warmup, HTTP interception, request injection, server middleware instrumentation, exact compiler/CPU attribution or cross-clock subtraction.
Sibling surfaces: both native modes, default/profile callers, success/action failure/readiness timeout, crash/disconnect/signals, page close and global cleanup, normal/compact publication and hostile browser payloads.

## Decisions

1. Reuse trailing `--profile`; do not add another flag or change CI eligibility. A new `summary.publicCreate` record exists only for the first click-to-created-editor attempt, not later SPA round trips or restart trials. Default calls retain their existing observation behavior and output shape.
2. Extend `observeNavigation` in place with an optional diagnostic sink rather than a parallel network observer. Arm measurement before the existing clock begins, with no deliberate delay. At `visitEditor`'s existing start, synchronously capture that exact collector start/deadline; capture action settlement and original assertion outcome without another wait or a replacement deadline.
3. Retain API item PUT/GET, editor RSC and script lifecycles from existing CDP listeners. Ignore standalone wrong-origin, unsupported-method and malformed request events without retaining strings or consuming capacity. For an admitted chain, consume `redirectResponse` into its preceding hop before reclassifying the replacement; requestId remains private correlation state, while each retained hop has a bounded local ordinal. Supported same-origin replacements retain their actual method/class. A cross-origin/unsupported replacement consumes one fixed `redirect-out-of-scope` terminal hop and tombstones the chain; later response/data/completion cannot attach to the preceding PUT. Every admitted hop counts toward64. Hop65 consumes the preceding redirectResponse, tombstones the chain instead of leaving hop64 current, increments a saturating omitted count and marks partial; all subsequent events for that chain are ignored, with no new unbounded tombstone allocation. Missing/invalid methods are unavailable, never inferred as PUT.
4. Keep collector receipt elapsed/epoch milliseconds, CDP Network timestamps/timing units, and browser performance timeOrigin/now separate. `Page.navigatedWithinDocument` records a SPA URL/history observation with a collector receipt if no browser timestamp exists; it is not a React/RSC commit. GET completion proves network delivery only, not parsing, repository resolution, `setLoaded`, EditorSession creation or rendering. Never infer an API response from the next request or an exact marker insertion from a later sample.
5. Install one opt-in, read-only page sampler before click; sample only marker presence, Playwright-compatible visible predicate (nonempty box and visibility not hidden/collapse; opacity alone is not invisibility), fixed route class and browser clock. Sample no faster than50ms, at most128 times; before any layout read, self-stop when browser elapsed time reaches6400ms from arming or the sample cap, whichever comes first. A delayed callback past expiry performs no layout read. This bounds work independently of collector disposal. Report first-observed visible plus the preceding observation bracket, not exact first visibility. Missing/stalled sampling is partial. Validate binding payloads before any sink; retain finite monotonically ordered timestamps only, reject out-of-order/duplicate samples with fixed partial status, and never rewrite a sealed bracket from a late reply.
6. Retain at most64 classified requests,16 route transitions,128 marker samples and one attempt. Limits bound memory/output and work; overflow carries fixed partial codes/counts. New commands use the existing1000ms diagnostic-operation ceiling; teardown fits existing browser close deadlines, without extending them.
7. Use armed→observing→success-finalization or failed-tail→finalized states, with per-channel abandonment on diagnostic-command timeout/disconnect/interruption. Original readiness timeout enters failed-tail; original outcome/deadline never change. Success fences collector acceptance before later navigation and requests bounded best-effort sampler disposal. Acknowledged disposal means stopped; timeout means `sampler-disposal-timeout` partial and shutdown unknown, not disposed. Proceed without retry or extra grace wait: bounded residual page work may continue until autonomous expiry/cap/page close, but no later observations are accepted. Failure keeps the preinstalled sampler running only through existing capture/teardown and its own bounds; collector receipt is passive, page layout sampling is not. Label every post-outcome receipt regardless of producer timestamp. Finalize at page close or before safe publication, whichever comes first; detach collector listeners and best-effort remove page timers/bindings. Setup/disposal are the only new commands, with1000ms ceilings inside existing close budgets; never wait for late-ready or extend capture. Abandoned epochs reject late setup/disposal replies before and after finalization; cleanup cannot re-arm or rewrite brackets.
8. Reconstruct `publicCreate` with fixed enums, finite numbers and validated provenance in the existing projection layer; preserve the1MiB total safe-summary limit. Compact overflow retains attempt identity, start/deadline/outcome and channel statuses/omission counts, never raw details. Original qualification result/artifacts and all prior profile/gap fields remain authoritative and unchanged.

## Risks / Trade-offs

- Sampling perturbs diagnostic timing → profile-only, bounded cadence/work, report first-observed brackets; never qualify the failed original with the replay.
- Unknown event ordering or missing API/DOM channel → retain explicit unknown/partial states, distinct clock domains and same-attempt ordinals; no interpolation.
- Observer callbacks after timeout or cleanup → immutable original outcome, lifecycle-owned detach/finalize, no late resurrection or cleanup extension.
- Browser-controlled strings and output overflow → fixed field reconstruction, hostile-input regressions and existing no-follow safe publisher; raw profiles remain private.
- Current failure may not recur in a later CI capture → report non-reproduction without a repair claim; do not rerun for green or demand an artificial timeout.

## Migration Plan

Implement in the current checkout only after apply authorization, on the independent branch based on frozen PR221; one implementer owns all source/test changes. Add behavioral red cases, cut over all new-channel producers/projectors/compact consumers atomically, then run the task matrix. Document interpretation at the native guide and record the new diagnostic choice without superseding0030. No persisted-format compatibility shim is required for a newly added optional channel.
Rollback removes only this opt-in channel and its callers; retain the base profiling safety, sole signal ownership, physical gaps and original qualification. Do not merge into PR221/219. A later retarget after dependencies land requires fresh scope inventory and checks.

## Verification

Tests target observer→runtime→safe-file behavior: PUT/RSC/GET, redirects reusing requestId, terminal exclusions, hop65 followed by response/data/completion, stale events, samples before/after outcome, caps, hostile payloads and held replies. Controlled Chromium changes URL or completes GET without a marker to prove no application commit is inferred. Test delayed visibility during existing failure capture; on success test both acknowledged disposal and a held disposal across timeout/homeBack, observing actual page-side work and collector rejection until autonomous expiry. These are measurement tests, not CI-defect reproductions. Real native profile runs in both modes/default/interruption prove restoration; new-head CI capture binds same-invocation evidence and preserves original failed qualification.
