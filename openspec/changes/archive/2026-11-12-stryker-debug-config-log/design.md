# Design

Change surface: `package.json` `pnpm.patchedDependencies`; `patches/@stryker-mutator__vitest-runner@10.1.1.patch` (generated by `pnpm patch` / `pnpm patch-commit`, edits shipped `dist/` JS only); `pnpm-lock.yaml` patch hash; one `node --test` regression file under `scripts/` with a `package.json` script, its AGENTS.md command-table row, and a CI step; decision record under `decisions/`; `docs/engineering/` note on maintaining dependency patches.

Must preserve:

- Installed versions stay exactly `@stryker-mutator/core@10.1.1`, `@stryker-mutator/vitest-runner@10.1.1`, Vitest 5.1.0; no other lockfile entry changes.
- Non-debug (info) runner behavior, `stryker.config.mjs`, mutation scope, thresholds, timeouts, CI time budgets (#88 territory) unchanged.
- The debug log still contains the final Vitest config: the message starts with `vitest final config:` and names at least the top-level keys `root`, `include` and `resolvedProjects`. Node `util.inspect` default depth-2 truncation (`[Object]`) is accepted, matching upstream #6261; a `[Circular` marker or nested fields are NOT asserted.
- Errors other than config logging still propagate; no try/catch swallowing in the runner.

Must add/change: debug-level config logging that cannot throw on circular or non-JSON values, matching upstream stryker-js#6261 (`this.log.debug('vitest final config: %O', this.ctx.config)` or equivalent) so the patch is a minimal diff against the published file.

Governing invariant: enabling Stryker debug logging never changes whether the Vitest runner initializes or which tests run.

Sibling surfaces:

- Existing dependency-maintenance mechanism: decision 0021, `patches/native/`, exact-version `pnpm.overrides`, postinstall guard `scripts/native-installed.mjs`, and `scripts/native-install.test.mjs` (copies only `patches/native`). The new decision states its relation to 0021 (parallel mechanism for JS-only dist patches; why overrides are not used) and the new patch file must coexist without breaking the native frozen-install contract or postinstall guard (`pnpm native:installed`, `pnpm native:install:test` still pass).
- Other `JSON.stringify` of runtime objects in the installed vitest-runner `dist/` (audit and list; fix only the confirmed debug config path, report others).
- `@stryker-mutator/util` `errorToString` (#119) — separate issue, not patched here.
- pnpm install path: frozen install in CI and Renovate PRs; a version bump must make the patch fail loudly or be removed, never silently skip.

Seams under test:

- The package `exports` only `.` and `./package.json`, so the regression imports the installed file by path: `node_modules/@stryker-mutator/vitest-runner/dist/src/vitest-test-runner.js`, resolved through the symlink to the `.pnpm` entry carrying the patch hash (never a copy). `createVitest` is stubbed through the mutable export object `vitestWrapper` (`dist/src/vitest-wrapper.js`) to return a ctx whose `config` is circular (`resolvedProjects[0].viteConfig.test` back-reference); the logger is a capturing fake with `isDebugEnabled()` true.
- `init()` writes `stryker-setup-<worker>.js` into `process.cwd()` (`vitest-test-runner.js:124`) and mutates `process.env.NODE_ENV`/`VITEST` (`:259-264`): the regression runs with a temporary cwd and restores env; the working tree is clean afterwards.
- End-to-end `stryker run --dryRunOnly` on the repository config at debug and info level.

Required evidence:

- Regression, debug path: unpatched 10.1.1 → `init()` rejects with `TypeError: Converting circular structure to JSON`; patched → resolves, and the captured debug message matches the must-preserve key list.
- Regression, error path: stubbed `createVitest` throws `Error('boom')` → `init()` rejects with that same error on both unpatched and patched (patch swallows nothing).
- Regression, non-debug: `isDebugEnabled()` false → no `vitest final config:` message, `init()` resolves.
- `pnpm exec stryker run --dryRunOnly --logLevel debug` → exit 0, output contains a `vitest final config:` line and `Initial test run succeeded. Ran N tests`; the same command at `--logLevel info` → exit 0, the same N, and no `vitest final config:` line.
- `pnpm install --frozen-lockfile` from clean `node_modules` → exit 0 and the installed file contains the patched line, not `JSON.stringify(this.ctx.config`.
- Failure path: a patch key for a non-installed version (or a non-applying patch) with `pnpm install --frozen-lockfile` → non-zero exit with an unused-patch / patch-failed error under pnpm 10.28 defaults (no `allowUnusedPatches` override exists in the repo). Measured, then reverted; recorded in the decision.

Non-goals: #119 formatter; #88 mutant-execution timeout; upgrading Stryker/Vitest; patching upstream source/TS; changing log levels used by CI.

Review focus: patch is minimal and matches upstream intent; regression actually exercises the installed patched file (not a copy); no lockfile drift beyond patch hash; decision record states maintenance and removal; CI wiring through existing gates.
